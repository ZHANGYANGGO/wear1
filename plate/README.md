# 山间食堂 · 厨房营业

双击[厨房营业-网页版.html](../厨房营业-网页版.html) 或本目录的 [index.html](index.html)。在「本局菜谱」中选四道菜中的一道，点地图卡片预览相应厨房，再确认进入准备。练习和营业都只供应这道菜。双人由房主确认菜谱和店面。单人可断网。

| 店面 | 尺寸（店内） | 默认动线 |
| --- | --- | --- |
| 街角小食堂 | 10 × 8 | 中部窗口交接，右侧双格通道往返。将水槽搬到前厅可缩短收盘路线。 |
| 中岛小馆 | 11 × 9 | 中央厨房占 5 × 5 格，墙沿格边。员工从右下开口进出，顾客沿外圈去左右两桌。 |
| 双窗小院 | 11 × 8 | 两扇窗各有一张普通传菜台，可按桌分工，也可左窗出餐、右窗回脏盘。 |

店外脚印通向入口，窗两侧可以操作同一张台面。打烊成功会自动进入商店，点「下一关」回到准备；营业失败可重试当前关。两者都保留摆位和禁坐设置，盘架恢复本店拥有的净盘数。换图或更换菜谱保留关号、钱包和整排货架，购买的家具和配件可从「摆放已购设备」重新放置。点「新开店」并确认后，从首关、零余额和三只盘开始。

### 打烊商店

每次成功打烊，实际餐费和优雅桌小费一起入账。五个货位里可以免费锁货，买走的格位显示售罄。付费刷新依次花 10、20、30……金币。下一次通关免费换货，锁定格保留，刷新费回到 10。购买独立设备时先点地图预览，可按 R 转向，确认后扣款。配件需要选空闲普通台面，盘包购买后立即加到盘架。

首日新货按表中价格出售。每多通过一关，新上架商品增加首日价的 10%，按最接近的整数元计价，半元向上取整。同日刷新使用当天价格，锁货保留上架时的报价。

同一浏览器再次打开原来的网页版会恢复店铺。结算、购买、换货和摆放都保存到本机。设备价格、抽货和交易在 [market.mjs](market.mjs)，选格和托盘动作在 [equipment.mjs](equipment.mjs)。

**移动和拿放。** WASD 或方向键平滑移动。沿台横移也能侧拿，同时按两个方向键可以指向露出的台角，松键后保留方向。空格用于拿放、装盘或上菜，E 用于接单、加工或刷盘。两个键各自在对应工位标出动作。盘架四周露出的边均可取盘，准备阶段按 R 旋转。点工位会自动走到手能够到的位置；目标物已被搭档取走时需重新操作。丢食物要指向或点选垃圾桶。

**通行和冲刺。** 斜走擦墙时可以沿边移动。门能从两侧推开，人离开后回摆；门扇受夹时暂时变透明让行。传菜窗挡住人物，贴窗的餐桌可直接接单、上菜与收盘。准备时把设备搬到门口会预览改窗，占用唯一通道时会提示原因。窄处与搭档或行走的顾客相遇会减速，让出一点位置即可错身。移动时按一下 Shift 沿当前方向立即短移最多一格，斜向等距，遇阻截停。端盘和拿托盘均可冲刺，松开 Shift 并等两秒冷却完毕后可再次使用。

**餐桌选座。** 准备时点餐桌，再点桌边的按钮切换禁坐。✓ 可坐，▧ 表示遮挡或无法从入口到达，× 表示主动禁坐，×▧ 表示两者重叠。点空地搬桌，按 R 转桌，禁坐标记随桌移动和旋转。每组独占一桌，单人优先坐小桌，双人要有两个可达座位才入座。前厅的厨师可从禁坐侧上菜、收盘。

**传菜台和备餐台。** 空格拿放或交换物品。一边是干净盘，另一边是一份成品时，空格装盘。拿着已经装盘的菜，面对空台面按 E 可以撤盘，手里拿回净盘，餐点留在台面。

**双人。** 两位玩家各打开同一版本的厨房页面并联网。房主创建房间并分享十位房间号，负责确认采购、摆放已购设备和开门。搭档可一起接单、做菜、收桌和使用设备。房主页面保持打开时，原搭档用同一浏览器重新加入房间，可恢复购物状态或营业中的角色和托盘。房主也可点「收回搭档持物到盘架」，随后空手去盘架领取；搭档回来时手部已腾空。

### 手作菜单

| 餐点 | 每份 | 做法 |
| --- | ---: | --- |
| 海苔饭团 | ¥12 | 熟饭与海苔放上料理台，按住 E 捏成一份。 |
| 黄瓜细卷 | ¥15 | 在料理台按住 E 把黄瓜切条，再配熟饭和海苔，按住 E 卷成一份。三种配料可按任意顺序放入。 |
| 厚蛋烧 | ¥10 | 在料理台打蛋，用平底锅煎成整条，起锅放在台面。拿净盘按空格，每次取一份，一条供两人。 |
| 牛排 | ¥18 | 将生牛排放进平底锅，到桌单要求的五分熟或全熟时空手起锅。送错熟度会保留原盘，可送去另一桌。 |

饭锅沿用 5 秒煮熟，熟饭可再留锅 8 秒。蛋液煎 4 秒成条，整条可再留锅 8 秒。牛排入锅后第 4 秒到五分熟，第 8 秒到全熟，第 14 秒焦糊。取出即停止加热。游戏中看锅旁进度条和文字起锅，焦料占锅时可空手取出。

三张店面各有一个垃圾桶，准备阶段点桶再点空地即可搬动。拿着食材、未装盘的成品或焦料，面对桶按空格即可永久丢弃。已装盘的菜要先在空台面按 E 撤盘，再单独拿起食物丢弃。盘子和厨具误投时会留在手里。

火候参数在 [content.mjs](content.mjs)，其中生米的初段时间沿用 [原饭团配置](upstream/recipe.mjs)。

**四盘水池。** 顾客离店后按空格逐只收盘，清空桌面即可翻台。水池可存四只脏盘，正在洗的一只也占位。按空格放盘，再点一次 E 连续刷。空手点只有脏盘的水池也能开刷。每只需 3 秒，走开或切出窗口会暂停，回到池边点 E 即可续刷。净盘留在池边，空手按一次空格或点一次水池取一只。净盘和脏盘同时存在时，空格取净盘，E 刷脏盘。两人可分工刷洗和取走净盘。

**练习。** 准备时点「练习」使用当前布局，一次接待一组。顾客耐心耗尽会离开，下一组会继续来。练习至少提供四只盘，方便试整池洗盘。结束练习后恢复本店正式库存和本关计划。双人房间由房主开始和结束练习。

练习的单组来客、超时换客和退出复位参照了 PlateUp! 的准备阶段。水池按本项目的规则点按启动、逐盘洗净和取回。[PlateUp! 官方 Wiki 的营业与练习说明](https://wiki.plateupgame.co.uk/en/gameplay/DailyOperations)

每关来客时段 60 秒，准备时显示本关组数和人数。首关 4 组 6 人，第二关 5 组 7 人，第三关 6 组 9 人。以后每关按单人、双人交替增加一组。首关全部出餐时，饭团店收入 72 元、细卷店 90 元、蛋烧店 60 元、牛排店 108 元。来客时段结束后可继续服务留下的客人。营业时段、顾客耐心、火候和刷盘均用进度条表示。冲刺参数、首关时刻表与后续来客生成分别见 [content.mjs](content.mjs) 中的 `dashSettings`、`levels.first` 和 `nextArrivals`。

## 开发与构建

在仓库根目录运行下列命令。新检出源码时先运行 `npm.cmd ci`。

```powershell
npm.cmd run build:kitchen
npm.cmd run dev
```

开发预览打开[本地厨房](http://127.0.0.1:5173/plate/index.html)。修改厨房源码后，运行 `npm.cmd run build:kitchen` 并刷新。根目录的厨房单文件与 `plate/index.html` 内容相同。运行 `npm.cmd run package:kitchen`（打包使用 Python 3.8+）可生成[厨房独立压缩包](../厨房营业-网页版.zip)，上传或解压后入口为 `index.html`。

## 添加工位、菜谱和地图

三类定义与关卡选择在 [content.mjs](content.mjs)。以下为独立的最小示例，快锅、双米饭团和派生地图共用一份[测试配置](tests/fixtures.mjs)。

**工位。** 复制已有工位能力，改变耗时与名称，然后让地图上的实例使用该种类。改变 `art` 可以选择其他绘制样式。新动作在 [game.mjs 的 actions 表](game.mjs) 注册，房主与单人共用处理函数。

```js
tools.quickPot = { ...tools.pot, name: "快煮锅", seconds: 1 };
map.fixtures.find(f => f.id === "pot").kind = "quickPot";
```

**菜谱。** 步骤的输入、输出均为物品 ID。配置菜单后，接单、做法提示、装盘、上菜和营业额共用菜谱。

```js
recipes.doubleRice = {
  name: "双米饭团", price: 19, product: "doubleRice",
  steps: [recipes.onigiri.steps[0],
    { action: "combine", inputs: ["cooked", "cooked"], output: "doubleRice" }],
};
level.menu = ["doubleRice"];
```

**地图。** 坐标从左上角的零开始。操作面方向依次为下、左、上、右，对应 0 至 3。地图同时定义边界、墙、出生点和排队格。格边支持 wall、window 和 door，设备占地与行走轮廓分别计算。下例从原图派生一张变体。

```js
maps.garden = structuredClone(maps.courtyard_diner);
maps.garden.name = "西门小院";
maps.garden.entry = [4, 7];
maps.garden.queue = [[4, 8], [3, 8], [2, 8], [1, 8]];
Object.assign(maps.garden.fixtures.find(f => f.id === "a"), { x: 1, y: 5 });
level.maps.push("garden");
```

`level.maps` 列出选图页开放的地图，`level.map` 指定其中首次预览的一张。只有 `level.map` 的关卡直接进入固定地图的准备阶段。三张正式地图共用关卡里的盘子数量、来客时间与人数、各阶段耐心、看菜单与用餐的时长。

## 验收

离线浏览器验收使用街角饭团、中岛蛋烧、双窗牛排，以及移动过水槽和垃圾桶的街角细卷布局。每组都从第 1 关开门，完成前两关，进入第 3 关并重试，逐关核对桌数、份数、金额和保留的座位设置。

**盘包对照。** 在同一街角布局、标准客流和菜价下，分别用细卷、牛排从第 2 关实际模拟经营到第 5 关。两种菜单得到相同洗盘次数。策略为等位时清桌、四盘水池和两张空台面暂存脏盘，缺净盘或暂存位满时手洗。各列为单关实际洗净只数。

| 首关采购 | 第 2 关 | 第 3 关 | 第 4 关 | 第 5 关 | 首次洗盘 |
| --- | ---: | ---: | ---: | ---: | --- |
| 原配三只盘 | 4 | 6 | 7 | 9 | 第 2 关 |
| 买 4 只装 | 0 | 2 | 3 | 5 | 第 3 关 |
| 买 8 只装 | 0 | 1 | 2 | 3 | 第 3 关 |

六组对照在第 2 至 5 关从桌上分别收回 5、7、8、9 只脏盘，分别清空 3、4、5、6 次桌面。买大包后，第 3 关因暂存位满洗了 1 只。首日买完 35 元的大盘包，细卷店余额为 55 元，牛排店为 73 元。对照通过游戏规则和虚拟时钟执行，包含真实寻路、备菜、上菜与清洗，脚本见 [market.test.mjs](tests/market.test.mjs)。
