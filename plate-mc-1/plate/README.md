# 山间食堂 · 厨房营业

双击本目录的 [index.html](index.html)，或从《搬家日》主菜单点击「厨房营业」。在「本局菜谱」中选四道菜中的一道，点地图卡片预览相应厨房，再确认进入准备。练习和营业都只供应这道菜。双人由房主确认菜谱和店面。单人可断网。

| 店面 | 尺寸（店内） | 默认动线 |
| --- | --- | --- |
| 街角小食堂 | 10 × 8 | 中部窗口交接，右侧双格通道往返。将水槽搬到前厅可缩短收盘路线。 |
| 中岛小馆 | 11 × 9 | 中央厨房占 5 × 5 格，墙沿格边。员工从右下开口进出，顾客沿外圈去左右两桌。 |
| 双窗小院 | 11 × 8 | 两扇窗各有一张普通传菜台，可按桌分工，也可左窗出餐、右窗回脏盘。 |

店外一排脚印指向入口。实墙和花池阻挡通行，窗两侧可以操作同一张普通台面。准备时点「更换菜谱或店面」可重新选择。取消或确认原组合会保留布置。调整过家具后确认更换菜谱或店面，会提示重置摆位。结算后可按原组合再玩一次，也可在原房间重新选择。

**移动和拿放。** WASD 或方向键平滑移动。空格在身边高亮的工位拿放、装盘或上菜，E 接单或工作。沿柜台横移后也能投料。米柜、饭锅、料理台、传菜台和水池四周的相邻通道都可操作。盘架和餐桌使用有金色标记的一面，准备时可按 R 转向。鼠标和触屏直接点工位会走近操作，场景下方还有独立的拿放和工作按钮。

**传菜台和备餐台。** 空格拿放或交换物品。一边是干净盘，另一边是一份成品时，空格装盘。拿着已经装盘的菜，面对空台面按 E 可以撤盘，手里拿回净盘，餐点留在台面。

**双人。** 两位玩家各打开同一版本的厨房页面并联网。选图时或准备时都可以建房和加入。房主点击「双人房间 → 创建房间」，将十位房间号发给搭档。两人可独立浏览地图，由房主确认店面并开门。准备中加入会收到当时的家具摆位。两人都能摆设备、接单、做菜和收桌。房主网页推进营业，需保持打开。搭档离开时，手中物品可从盘架取回。

### 手作菜单

| 餐点 | 每份 | 做法 |
| --- | ---: | --- |
| 海苔饭团 | ¥12 | 熟饭与海苔放上料理台，按住 E 捏成一份。 |
| 黄瓜细卷 | ¥15 | 在料理台按住 E 把黄瓜切条，再配熟饭和海苔，按住 E 卷成一份。三种配料可按任意顺序放入。 |
| 厚蛋烧 | ¥10 | 在料理台打蛋，用平底锅煎成整条，起锅放在台面。拿净盘按空格，每次取一份，一条供两人。 |
| 牛排 | ¥18 | 将生牛排放进平底锅，到桌单要求的五分熟或全熟时空手起锅。送错熟度会保留原盘，可送去另一桌。 |

饭锅沿用 5 秒煮熟，熟饭可再留锅 8 秒。蛋液煎 4 秒成条，整条可再留锅 8 秒。牛排入锅后第 4 秒到五分熟，第 8 秒到全熟，第 14 秒焦糊。取出即停止加热。游戏中看锅旁进度条和文字起锅，焦料占锅时可空手取出。

三张店面各有一个垃圾桶，准备阶段点桶再点空地即可搬动。拿着食材、未装盘的成品或焦料，面对桶按空格即可永久丢弃。已装盘的菜要先在空台面按 E 撤盘，再单独拿起食物丢弃。盘子和厨具误投时会留在手里。

火候参数在 [content.mjs](content.mjs)，其中生米的初段时间沿用 [原饭团配置](upstream/recipe.mjs)。

**四盘水池。** 顾客离店后按空格逐只收盘，清空桌面即可翻台。水池可存四只脏盘，正在洗的一只也占位。按空格放盘，再点一次 E 连续刷。空手点只有脏盘的水池也能开刷。每只需 3 秒，走开或切出窗口会暂停，回到池边点 E 即可续刷。净盘留在池边，空手按一次空格或点一次水池取一只。净盘和脏盘同时存在时，空格取净盘，E 刷脏盘。两人可分工刷洗和取走净盘。

**练习。** 准备时点「练习」使用当前布局，一次接待一组。顾客耐心耗尽会离开，下一组会继续来。练习提供四只盘，方便试整池洗盘。点「结束练习」恢复摆位，正式首关从三只干净盘和零收入开始。双人房间由房主开始和结束练习。

练习的单组来客、超时换客和退出复位参照了 PlateUp! 的准备阶段。水池按本项目的规则点按启动、逐盘洗净和取回。[PlateUp! 官方 Wiki 的营业与练习说明](https://wiki.plateupgame.co.uk/en/gameplay/DailyOperations)

默认来客时段 60 秒，共 4 桌 6 位。全部出餐后，饭团店收入 72 元、细卷店 90 元、蛋烧店 60 元、牛排店 108 元。来客时段结束后可继续服务留下的客人。营业时段、顾客耐心、火候和刷盘均用进度条表示。

## 开发与构建

在仓库根目录运行下列命令。新检出源码时先运行 `npm.cmd ci`。

```powershell
npm.cmd run build
npm.cmd run dev
```

开发入口为 [本地主菜单](http://127.0.0.1:5173/) 或 [本地厨房](http://127.0.0.1:5173/plate/index.html)。单独改厨房源码后运行 `node plate/build.mjs` 并刷新厨房页面。运行 `npm.cmd run build` 会重新生成含搬家和三张厨房地图的 [完整单文件网页版](../搬家日-网页版.html)，同时输出 `dist/index.html` 和仅含厨房的 `dist/plate/index.html`。

## 添加工位、菜谱和地图

三类定义与关卡选择在 [content.mjs](content.mjs)。以下为独立的最小示例，快锅、双米饭团和派生地图共用一份[测试配置](tests/fixtures.mjs)。

**工位。** 复制已有工位能力，改变耗时与名称，然后让地图上的实例使用该种类。改变 `art` 可以选择其他绘制样式。新动作在 [game.mjs 的 actions 表](game.mjs) 注册，房主与单人共用处理函数。

```js
tools.quickPot = { ...tools.pot, name: "快煮锅", seconds: 1 };
map.fixtures.find(f => f.id === "pot").kind = "quickPot";
```

**菜谱。** 步骤的输入、输出均为物品 ID。配置菜单后，接单、做法提示、装盘、上菜和营业额共用菜谱。

```js
recipes.doubleRice = {
  name: "双米饭团", price: 19, product: "doubleRice",
  steps: [recipes.onigiri.steps[0],
    { action: "combine", inputs: ["cooked", "cooked"], output: "doubleRice" }],
};
level.menu = ["doubleRice"];
```

**地图。** 坐标从左上角的零开始。操作面方向依次为下、左、上、右，对应 0 至 3。地图同时定义边界、墙、出生点和排队格。下例从原图派生一张变体。

```js
maps.garden = structuredClone(maps.courtyard_diner);
maps.garden.name = "西门小院";
maps.garden.entry = [4, 7];
maps.garden.queue = [[4, 8], [3, 8], [2, 8], [1, 8]];
Object.assign(maps.garden.fixtures.find(f => f.id === "a"), { x: 1, y: 5 });
level.maps.push("garden");
```

`level.maps` 列出选图页开放的地图，`level.map` 指定其中首次预览的一张。只有 `level.map` 的关卡直接进入固定地图的准备阶段。三张正式地图共用关卡里的盘子数量、来客时间与人数、各阶段耐心、看菜单与用餐的时长。

## 验收

离线浏览器验收使用街角饭团、中岛蛋烧、双窗牛排，以及移动过水槽和垃圾桶的街角细卷布局。每局分别检查唯一的菜单、对应工位、六份订单和按所选菜价计算的营业额。

```powershell
npm.cmd test
node plate/tests/browser.mjs --offline
node plate/tests/browser.mjs --duo
node plate/tests/browser.mjs --duo --public
```

- **火候与菜单。** 逻辑测试覆盖熟度切换临界点、离火保存、焦料占锅、误投、重做和盘数守恒。浏览器使用真实工位和桌单验证冷饭再用、切卷、整条蛋烧跨桌分份，以及两种熟度牛排交付。
- **第二轮 · 四盘水池、捏制和练习。** 逻辑测试覆盖第五只脏盘留在手中、两人同刷共用进度、洗净后逐只取、捏制中断续作、练习超时换客和恢复正式库存。断网 Chrome 的 390 像素触屏模拟中，服务两桌并收齐四只脏盘，点一次水池刷完四只，持有净盘后再次点击拿放仍只持有一只。
- **双窗口。** 两个浏览器会话通过本机信令建立真实 WebRTC 连接，验证共享熟度、争同一锅牛排、传菜台交接、争最后一份蛋烧、移动垃圾桶、换图和洗盘接力。可通过 `--public` 另行测试公共配对服务。
- **待真人验证。** 两台真设备分处 Wi-Fi 与移动网络时的连接和手感，以及新玩家是否会在第二次开店时主动换布局或改变先做哪件事。

饭团原料和加工时间取自 Delixia 的固定提交，实际改编说明和许可在 [upstream/README.md](upstream/README.md)。场景、角色、工位和菜品图形由本项目绘制。
