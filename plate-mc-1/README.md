# 今天应该很顺利 · 搬家日

在一局里连续接两份公寓搬家订单。交齐长沙发、一箱书和一盆绿植，基础款 120，出车成本 100。剩余时间可以继续装货，也可以到车尾提前收工。第一单挣的钱能用于第二单，双人共用同一笔钱和同一套装备。

主菜单另有「厨房营业」。选一家店面，从海苔饭团、黄瓜细卷、厚蛋烧和牛排中选一道，用三只盘子经营一天。顾客只点本局选定的菜，牛排订单还会指定熟度。[厨房独立版](plate/index.html) · [玩法和双人说明](plate/README.md)

## 直接打开游戏

双击 [搬家日-网页版.html](搬家日-网页版.html) 即可游玩。这个文件包含搬家玩法、厨房营业和三张厨房地图，可以单独复制或改名。点「开始新游戏」进入搬家玩法，点「厨房营业」进入选图，在厨房点「返回搬家日」回到主菜单。单人可断网，双人联机时需要联网。

两台电脑各自打开本地文件时，双方先联网，房主点「双人搬家 → 创建房间 → 复制房间号」，搭档点「双人搬家」，输入房间号加入。

## 静态网页发布与双人邀请

完整构建会同时生成网页版 HTML 和内容相同的 [dist/index.html](dist/index.html)。把这份 `index.html` 上传到 HTTPS 静态站点即可发布全部玩法，支持网站子目录。也可上传「搬家日-网页版.zip」，入口是压缩包根目录的 `index.html`。源码开发、重新构建和本地预览使用 Node.js。

1. 房主打开已发布的网址，选择「双人搬家 → 创建房间 → 复制邀请链接」。搭档打开链接即可入房，也可以在同一游戏页面输入 10 位房间号。请分享搭档设备可以访问的静态站点网址。
2. 房主页面用 Matter.js 推进两人的搬运物理，统一处理签收、采购、亏损选择与发车截止时刻。搭档通过 WebRTC 发送输入，接收同一份货单与钱包。PeerJS 客户端随网页打包，选择双人模式时才连接配对服务。公共 PeerServer 用于建立连接，网络条件需要时 WebRTC 可使用 PeerJS 默认配置的 TURN 中继。配对和中继的可用性取决于玩家网络及公共服务。[PeerJS 连接机制](https://peerjs.com/client/getting-started)
3. 搭档离开会释放抓点，可用原链接回来。房主页面将物理进度定期写入浏览器本地存储，采购和关卡选择立即保存。房主刷新后恢复同一订单，搭档自动重连。房主关闭标签页后可在同一浏览器、同一站点选择「双人搬家 → 恢复上次主持的房间」。离线时间仍计入已经开表的订单。搭档自动重连等待约 25 秒，之后可再次打开原邀请。房主切回「单人试玩」后可用「恢复上次主持的房间」继续。
4. 跨网络验收可让电脑连 Wi‑Fi、手机用移动数据，通过同一邀请完成合抬，再在买车后刷新房主，核对余额、库存和下一单车厢。公共服务或目标网络禁止连通时，页面会提示重试。

## 源码开发与本地预览

使用 Node.js 22.12 或更高版本。在项目目录运行以下 PowerShell 命令。已安装依赖时可以直接运行第二行。

```powershell
npm.cmd ci
npm.cmd run dev
```

打开 [本地单人入口](http://127.0.0.1:5173/)，点「开始新游戏」，读完订单后点「开始搬运」。这时才开始六分钟倒计时。双人由一人点「双人搬家 → 创建房间」，另一人用邀请链接或房间号加入。双方可以合抬沙发、分别送货、代全队采购或提交关卡选择。开发预览默认使用本机端口 5173，修改 `PORT` 可更换端口。

| 固定入口 | 用途 |
|---|---|
| [正常两关，种子 7](http://127.0.0.1:5173/?seed=7) | 第一关晴，第二关有雨。新局余额 0，配基础车。 |
| [首关下雨](http://127.0.0.1:5173/?order=rain&seed=7) | 书箱摆在小院。种子 7 在开表 19 秒时出现预兆，31 秒时下雨，持续 12 秒。 |
| [短时限](http://127.0.0.1:5173/?order=short) · [打平测试单](http://127.0.0.1:5173/?order=even) | 两者均为 12 秒，便于复测到点和刷新。打平单基础款、出车成本都是 120，规则测试把货放到指定边界条件。 |
| [模块 2 练习场](http://127.0.0.1:5173/?order=practice) | 原尺寸车厢，可在随车工具区切换干箱和湿箱，练习室内和小院两条路线。 |

### 搬运与结算

- WASD 或方向键移动，空格抓取和松手，Q/E 转向。沙发可两人各抓一端，单人可先在一端按 F 垫滑板，再抓另一端。搬盆栽时按住 Q 或 E 扶稳，急转掉土会扣 25。触屏可用地图下方按钮。
- 折叠桌每张 12，两张独立计价。落地灯 20。穿衣镜完好 35，磕坏后 15。把货物完整放进货厢并松手放稳约半秒后才首次签收。重新抓起时勾选保留，越出边界即撤销，回厢放稳可以重新签收。
- 屋内和小院屋檐能遮雨。买了防雨布后，空手靠近书箱按 F 可以盖好。露天书箱受潮，可就地按 F 消耗一卷胶带，或把推车移到箱旁按 F 转装。转装后运的是推车上的书，原箱为空箱。
- 车尾关门或倒计时归零时锁定货单。三件交齐且有盈余或打平，自动过关。若净亏 5，点「接受亏损并继续」就从本局钱包扣 5，余额可到 −5；点「重试本关」则保留关前的钱包、装备和种子，恢复完整时限。到点缺件时，回执列出缺项，重试该关。
- 关间可花 40 买加宽货车，或花 15 买可重复使用的防雨布。采购和读回执均不计时。末关显示累计净收益和结束余额。点「开始新游戏」会回到第一关。单人进度保存在当前标签页，刷新沿用原截止时刻。双人进度保存在房主浏览器，搭档使用原邀请链接重连。

## 构建与验证

```powershell
npm.cmd test
npm.cmd run build
npm.cmd start
```

前两行分别运行物理与经营规则测试、生成生产版。第三行用 Vite 在本机预览静态产物，默认端口与开发预览相同。发布后可关闭预览。浏览器验收脚本读取开发服务器上的角色位置辅助走位，用真实键盘、触控或页面按钮操作。可用 `BROWSER_PATH` 指定 Chromium，`TEST_URL` 指定开发服务器。以下命令在开发服务运行期间于另一终端执行。

```powershell
$env:CAMPAIGN='solo'
node tests/browser.mjs
```

将 `CAMPAIGN` 换成 `ledger`、`packing`、`tarp`、`loss`、`duo`、`lossduo` 或 `extension`，可分别复测装卸计价、不同装法、防雨布、亏损存档、团队采购、双方选择冲突和新增车型。用 `weather` 时将 `TEST_URL` 设为上表首关下雨的地址；用 `refresh` 或 `deadline-duo` 时设为短时限地址。清除这两个环境变量并执行同一脚本可复测原模块 2。

### 静态版回归

构建后运行 `node tests/static-room.mjs --offline` 可断网检查本地文件启动、样式、地图与存档。用 `--file --public` 可复测本地文件通过房间号加入。运行 `node tests/static-room.mjs --public` 可用两个独立 Chrome 会话测试真实公共配对和 WebRTC。脚本仅向浏览器提供成品文件，覆盖子目录部署、邀请、满房、搭档操作、双方刷新、截止时刻和房主重开标签页。`node tests/static-room.mjs` 用测试夹具转交配对消息，游戏数据仍经过真实 WebRTC。经营脚本的 `CAMPAIGN=duo` 包含共同买车后刷新房主的核对。复测需要浏览器能建立 WebRTC 数据连接。本机两组 Chrome 会话实测了公共配对、静态包邀请、双人合挣 40 同购一辆车、买车后刷新并进入第二关。另用 WebRTC 回归了合抬过弯、离开时松手和亏损回执相反选择。Wi‑Fi 与手机移动网络之间的实机连通性仍待验证。

### 模块 3 验收记录

本轮运行了 13 项自动化规则测试，其中 6 项覆盖原有搬运物理，7 项覆盖经营和关卡边界。下表记录固定输入测试与 Chrome 窗口实搬覆盖的内容。

| 项目 | 规则测试 | 浏览器操作 |
|---|---|---|
| A · 逐件计价 | 三件完好净赚 20，盆栽损坏净亏 5，再带灯净赚 15。装灯、卸灯、装回，实收依次为 115、95、115。两张桌分别计价，受损镜按 15 计一次。 | 正常入口搬齐三件再装灯，第一单净赚 40。另一次故意让盆栽掉土，实际装灯、卸灯再装回，界面实收依次为 115、95、115，净收益最终为 15，关门前钱包仍为 0。 |
| B · 截止和回执 | 覆盖盈利、打平、亏损、缺件。把最后一件安排在截止前恰好稳定 33 步或仅 32 步，结果分别为签收、缺件。已签收货在厢内重抓可交付，未首次签收的在手货不计。同一步关门和到点只处理一次。 | 短单刷新后继续倒计时，到点显示缺件，刷新回执仍可重试。两窗口共同到点，看到相同结果。对同一份单人亏损存档分别重试和接受，刷新后前者回到原关、余额 0，后者进入采购、余额 −5。 |
| C · 装车与降雨 | 同种子下复测屋檐、防雨布与湿书转装。把桌放到载书推车的位置，碰撞将两件分开。 | 基础车的尾部窄位能放折叠桌，完好三件加桌净赚 32。卸桌、把盆栽移到边上，再转动镜子通过门厅，受损镜随车净赚 35。另用种子 7 连开两次，第一回把书箱放在屋檐下保干，第二回让书淋湿后转上推车，推车占了原来放桌的车尾位置，仍剩一卷胶带。 |
| D · 采购与新局 | 校验余额不足、唯一装备重复购买和相同操作重复提交。对照同一组装载坐标，基础车与宽车分别签收三件、三件加灯。 | 首关实赚 40，买车后刷新仍有一辆，第二关把灯装在横坐标 759 的新增空间，基础车右界为 691。另一次花 15 买雨布，在第二关盖住室外书箱，雨后仍干。末关结算核对累计收益与余额，再开新局恢复首关、余额 0、基础车。 |
| E · 目录扩展 | 测试目录加一把报价 8 的折椅，自动生成物件、签收和账单行。仅加车辆条目即可购买、保存、装备并将下一单的签收区改宽到 350。 | 以测试目录启动同一客户端，商店自动出现 21 元试验车型。用首单收入购买，刷新后余额 19，切回基础车再装备试验车型，下一关车宽为 350。 |
| F · 双人共享 | 复测抓点归属、断线释放、共享回执并对同一待选结果依次投递相反选择。 | 两个独立窗口分别送必搬货和灯，共挣 40。同时购买大车，两边均为余额 0、库存 1，下一单车宽均为 322。同时提交接受亏损和重试，本次房间选中接受，两端同到采购页，余额 −5。另在练习场复测同端争抢、合抬过弯、松手接手、单人继续搬进车厢和两边同步签收。 |

**真人节奏待测。** 单人脚本按已知路线约 30 秒搬齐三件，双窗口经营脚本一次为 48 秒。两者使用精确坐标辅助走位。复测真人时，请新玩家从正常入口用基础车开第一单，从按「开始搬运」计到货单首次达到 3/3，再记录是否主动回屋搬额外货。首单暂保留六分钟，待取得真人记录后判断“四分钟搬齐、余两分钟”的目标。

### 追加收费货物与采购商品

[订单货物目录](shared/catalog.ts) 定义种类、实例摆位、订单时限和金额。[可购买商品目录](shared/equipment.ts) 定义稳定商品 ID、价格、持有上限及效果。下面是测试用配置，正式订单未投放这些条目。

新增一种收费货物，在货物目录和摆位表各加一条即可。每个摆位需要独立 ID，可复用现有绘制样式。

```ts
freightCatalog.stool = { name: "折椅", w: 22, h: 20, price: 8, art: "table", risk: "轻便" };
placements.push({ id: "chair-1", kind: "stool", x: 191, y: 335 });
```

新增车辆档位，在商品目录加一条。同类车辆共用购买、装备、存档和构造车厢逻辑。持有上限 1 表示唯一装备。

```ts
products.testVan = { name: "试验车型", price: 21, limit: 1, effect: "vehicle", width: 350 };
```

[经营逻辑](shared/campaign.ts) 处理计时、回执、采购和关卡推进；[物理世界](shared/moving.ts) 处理碰撞、签收与降雨。[单人会话](src/session.ts) 与[房主网页](src/browser-room.ts) 共用经营逻辑。[订单界面](src/orders.ts) 显示报价和回执，[地图绘制](src/art.ts) 读取本单的车厢和货物尺寸。

生产构建另用独立端口验证了菜单、开表、建房、邀请链接及双方账单显示。

### 模块 2 验收记录

以下 A–E 使用本机 Chrome 自动化实测。脚本读取位置辅助走位，通过页面按钮和键盘控制角色，从正常出生点完成搬运。双人使用独立浏览器会话。

| 项目 | 实测结果 |
|---|---|
| A · 室内 | 装滑板、抓另一端，沙发转过门厅直角。书和盆栽也经室内路线装车，货单依次为 1/3、2/3、3/3。 |
| B · 小院 | 先运盆栽。推车停在院门中央时，向南拖动的沙发被挡住。单人把车挪开，沙发通过，三件都经小院签收。 |
| C · 湿箱 | 从同一湿箱开局分别贴胶带、推车转装。两次均只签收一份书，胶带分别剩 0 卷、1 卷。连续按 F 后，载书位置与余量正确。 |
| D · 卸货 | 满车时抓住推车仍为 3/3。越界为 2/3，推回并松手放稳恢复 3/3。重开湿箱局后，货物、工具、货单与抓点恢复初始状态。 |
| E · 双人回归 | 房间号和邀请链接均可加入。两人各抓一端转弯，一人松手后另一人完成装车，两端均勾选沙发并显示 1/3。同端争抢、断线释放、同步重开通过。 |

另有 6 项物理规则测试，覆盖签收边界、重抓、卸货、抓点归属、滑板与合抬、盆栽急转与扶稳、空箱和空车的货单判定。390 × 844 触屏模拟验证了方向、转向、抓取和工具按钮。生产构建已验证普通订单、切换湿箱局和双窗口抓取。

真人自由选路的理由、手机真机手感和跨设备网络仍待实机试玩。自由选路时只给玩家货单，观察他分别如何搬沙发与书箱，结束后询问选路原因。
