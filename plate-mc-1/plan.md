# 任务一｜让一家饭团店完整营业一天

请在当前《搬家日》仓库实现一个可单人、可双人联机的网页厨房关卡。从项目主菜单进入「厨房营业」，玩家能布置店面、开门迎客、备餐上菜、收桌洗盘，直到当天营业成功或失败。首版开放**一张地图、一道菜「海苔饭团」**。请直接实现并运行验收。

## 一、接入现有工程

厨房实现放入当前仓库的 plate/，从原主菜单进入。沿用纯网页交付方式与 PeerJS 配对。参考 Delixia 的食材、加工、持物与台面交互，记录实际采用的版本和内容，保留对应许可与素材署名。[Delixia 参考仓库](https://github.com/TriForMine/Delixia)

## 二、开店前，玩家可以自己摆厨房

首图提供前厅、后厨、顾客入口、两张各坐两人的餐桌，以及米、海苔、锅、料理台、普通台面和水槽。关卡配置默认提供三只干净盘子。默认布局要让新玩家直接开门就能玩。

准备阶段可以搬动和转向设备、台面和餐桌。把水槽摆近前厅，可以缩短收盘路线；把料理台摆在出餐口，可以方便两人传菜。移动后，碰撞、工位交互和顾客找桌都使用新位置。若布局堵死了必经通道，开店前指出具体位置，允许玩家继续调整。房主确认开门后固定布局，开始计算营业时间。

## 三、营业中，玩家自己判断先做哪件事

**接待与点单。** 顾客分批到店。首关安排单人客和双人客。有座位足够、可到达且已经收干净的桌子时，整组入座，其余人在门外等。入座的顾客先看菜单，准备好后示意，玩家走到桌边接单。桌上显示还欠哪些菜、各几份。两人桌上了第一份饭团后，仍能清楚看到还欠一份，两份上齐才开始用餐。

**备餐与上菜。** 厨房从开门起就能备菜。玩家取米下锅，煮饭期间可以离开去接单或收桌。熟饭配上海苔做成饭团，用干净盘子装好，再送到已点这道菜的桌边。饭团做好时不绑定顾客。两桌都点了饭团，玩家手里只有一盘，就可以先送给等得更久的那桌。不符合需求的上菜操作保留手里的餐点，并提示原因。

**收桌与洗盘。** 顾客离店后逐只收盘，清空桌面即可翻台。水池最多收四只脏盘，正在刷的那只也占一个位置。站在水池旁，按空格放入手中脏盘，点一次 E 连续刷完整批。走开后保留当前进度，搭档可接手。洗好的盘子叠在池边，空手按一次空格取一只，可直接去装盘或送回盘架。鼠标和触屏可以直接点水池放盘、开始刷洗或取一只净盘。

**现场反馈。** WASD 连续移动，空格就地拿放、装盘和上菜，E 接单或工作。料理台配料齐后按住 E 捏饭团，松开可续捏。点击工位可以自动走近。营业时段和顾客耐心用剩余进度条，料理台和水池显示手头这件工作的进度。双人桌保留已经上桌的饭团，同时显示欠菜。门外排队、桌面脏盘和另一桌的耐心都能在场景内看见。

**营业前练习。** 房主可在当前布局进入练习，一次来一组客人，超时换客。练习提供四只盘以试用整池容量。退出后保留开练前的布局，正式营业从三只干净盘和零收入开始。

## 四、打烊、胜负和联机

**营业时钟管当天的来客时段。** 归零后停止来客，已经排队、入座或用餐的客人继续走完流程。当时钟已归零且门外与店内顾客组数均为零，成功打烊。最后一桌留下的脏盘不阻挡结算。按组分别计算等位、等接单与等上菜的耐心，双人桌收到第一份后沿用原上菜截止时刻。任一组耐心耗尽即失败，指出组号与等待原因。结算显示服务桌数、售出份数、营业额和结果。

**单人能独立经营，双人能随时换手。** 房主一个人就能开店，第二位玩家也能通过房间入口加入准备中的同一局。两人都能接单、备餐、上菜、洗盘，任何可放物的普通台面都能交接半成品。玩家可以一人掌勺、一人跑堂，也可以在前厅积了两桌脏盘时一起收桌。

单人在本机推进营业。双人由房主浏览器运行同一套规则，裁决摆位、物品归属、点单、耐心、时钟和结算，搭档通过 PeerJS 发送操作。同房重开回到准备阶段，顾客、盘子、订单和收入恢复本局初始状态。

## 五、工具、菜谱和地图必须能实际扩展

三类内容使用稳定 ID，显示、单人模拟和房主判定读取一致的定义。

| 扩展项 | 加入新内容时应当怎么做 |
| --- | --- |
| **工具与工位** | 定义名称、外观、支持的动作及参数。加一台快煮锅时，复用煮饭动作，只改外观和耗时。以后增加全新动作时，有明确的处理函数注册位置。 |
| **菜谱** | 定义原料、加工或组合步骤、所需工位能力、成品和售价。关卡按菜谱 ID 配置菜单，点单、做法提示、上菜和计价共用这份定义。使用已有动作的新菜可以通过配置接入。 |
| **地图** | 定义布局、通道、玩家出生点、顾客入口和排队区、餐桌与工位初始摆位。房间按地图 ID 加载，寻路和上菜读取本局实际摆位。关卡配置选择地图、菜单、客流、耐心和营业时长。 |

## 六、验收与交付

1. **单人营业。** 从主菜单开店，移动一件设备后，用新布局完整服务一桌双人客。验证第一份上桌后仍欠一份，清桌后下一组能坐下，洗出的盘子能再次装菜。
2. **打烊与失败。** 用短营业时段复测。归零时门外还有一组人，继续接待并服务完这组，可以成功打烊。另开一局让顾客等到失去耐心，验证失败原因。同房重开，确认每局只产生一次结算，上一局数据已清空。
3. **双窗口合作。** 两个独立浏览器窗口进同一房间。甲先煮饭，乙从普通台面接手装盘上菜，再交换一次前后厅分工。两人同时拿同一件物品，只有一人拿到；同时交最后一份菜，只计一份。核对两端的摆位、桌单和结算。
4. **三个扩展接口。** 只在测试配置中分别加入快煮锅、一道沿用已有动作的新菜、一张移动了入口和餐桌的地图变体。实际测到煮饭变快、新菜能从点单做到上桌、顾客从新入口走到新桌且旧位置无法上菜。正式首关只开放饭团店。
5. **交付说明。** 给出实际启动命令、单人和双窗口入口、操作键、三个扩展入口的真实文件路径，以及各自一个最小配置示例。分别列出浏览器实测、逻辑测试和待验证项。设备采购、跨天经营和后续正式关卡留给下一项任务。

6. **离线成品。** 关闭开发服务，使用无缓存、断网的浏览器从成品 HTML 主菜单进入厨房，独自营业到成功打烊。
7. **耐心与盘子。** 覆盖双人桌及时补齐和只上一份直到超时。安排两桌双人客各得一盘，用第三只盘让其中一桌开吃，再收盘翻台、洗净并给另一桌补齐，核对总盘数始终为三。
